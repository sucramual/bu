# ADR-001: Force-recycle only exact merged heads [status: accepted]

- **Context:** Durable benches often retain generated controller, configuration, or handoff changes after their pull request has merged. These dirty worktrees block ordinary recycling even when the checked-out commit is already preserved by GitHub.
- **Decision:** Status classifies a dirty bench as `forceable` only when every existing branch, operation, stand-in, and upstream check passes and exactly one merged pull request head equals local `HEAD`. Ordinary recycle remains non-destructive. `bu recycle --force` repeats the checks immediately, runs `git reset --hard HEAD` and `git clean -fd`, verifies the feature ref, stash, and clean state, then follows the existing stand-in update and switch path.
- **Alternatives:** Automatic cleanup during ordinary recycle was rejected because it hides an irreversible action. Stashing was rejected because these post-merge files are intentionally disposable and automatic stashes create later cleanup work. Treating any merged pull request as sufficient was rejected because local commits after the merged head would then lose uncommitted work under the wrong proof boundary.
- **Consequences:** Staged, unstaged, and untracked files can be permanently deleted after an explicit flag. Ignored files and existing stashes remain. A missing, unmerged, ambiguous, or non-matching pull request stays blocked. Cleanup failures report the failed phase and remaining dirty paths because reset and clean are separate commands.
