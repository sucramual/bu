# ADR-002: Observe scratch worktrees concurrently [status: accepted]

- **Context:** `bu prune --dry-run` took about 15 seconds on a repository with 13 scratch worktrees. `bu` observed each worktree one after another. Each observation runs about eight subprocesses: Git checks for the root folder, branch, status, and in-progress operations, plus one `gh pr list` call. The `gh` call is a network request that takes 0.5 to 1 second. The time was spent waiting, not computing.
- **Decision:** `bu prune` now observes and classifies scratch worktrees on scoped threads (`std::thread::scope`, threads that must finish before the function returns). It splits the scratch worktrees into at most 8 equal chunks, one thread per chunk. The cap keeps one run from sending more than 8 GitHub requests at once. The cheap checks stay serial: locked, missing folder, and contains the current directory. Results are put back in `git worktree list` order, so the output does not change. Removal stays serial. `remove_scratch` still lists the worktrees and repeats every check from ADR-001 immediately before each removal, and `git worktree prune` still runs at most once.
- **Alternatives:** An async runtime or a thread-pool crate was rejected because the work is a few blocking subprocesses and the standard library is enough. A shared work queue balances slow `gh` calls slightly better, but chunking keeps the order with no extra bookkeeping. Parallel removal was rejected because removals change shared Git state (the worktree list and branch refs). Doing them one at a time keeps each recheck accurate and each failure easy to read. An unbounded thread count was rejected because many scratch worktrees would mean many parallel `gh` calls and a faster path to GitHub's rate limit.
- **Consequences:** A dry run now takes roughly the time of the slowest chunk instead of the sum of all observations. The number of `gh` calls per run is unchanged; only their timing overlaps. Up to 8 `git status` commands can run at once, each in its own worktree, so they do not compete for the same index lock. A real prune still pays the full serial recheck cost per removed worktree, which is the price of the safety boundary in ADR-001.
