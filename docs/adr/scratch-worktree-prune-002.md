# ADR-002: Block pruning while a process uses the worktree [status: accepted]

- **Context:** A daily launchd job runs `bu prune` unattended. ADR-001 checks Git and GitHub state only. A merged, clean worktree can still host a live process, such as a docs dev server (`node`, `esbuild`) started from inside it. `bu prune` marked such a worktree prunable. Removing it would pull the folder out from under the running server.
- **Decision:** A scratch worktree is blocked when any process other than `bu` has its current working directory at the worktree path or below it. `bu` runs one `lsof -d cwd -Fpcn` per inspection pass: once before classification, and again immediately before each removal, after the pull-request lookup. It resolves symlinks on both sides and compares whole path components, so `/tmp` matches `/private/tmp` and `/a/wt` does not match `/a/wt-2`. The row reads like `in use by 7 processes (esbuild, node)`. If the first check cannot start `lsof`, sees a nonzero exit, or cannot parse the output, the run changes nothing and exits nonzero. An unknown process list never counts as "not in use". The one exception is exit status 1 with output. `lsof` uses it when it cannot inspect some processes, and the printed records are still used. A failed pre-removal check fails that worktree only. `status` and `recycle` do not run this check.
- **Alternatives:** `lsof +D <worktree>` would also find open files, but it walks the whole tree. That is too slow on `node_modules`. Scanning every open file of every process with plain `lsof` has the same cost problem and much larger output. The chosen check reads one small record per process.
- **Consequences:** Dev servers, shells, and editors started inside a worktree keep it alive until they exit or move. A process that holds files open in the worktree but has its current directory elsewhere is not detected. Neither is a process that `lsof` cannot inspect, such as one owned by another user when `bu` does not run as root. Git's own checks and the recheck window still apply. Each check takes a few seconds on a busy machine. That cost is paid once per run and once per removal.
