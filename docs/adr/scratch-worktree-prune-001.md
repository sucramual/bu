# ADR-001: Prune scratch worktrees only at exact merged heads [status: accepted]

- **Context:** Agents and short tasks create one throwaway worktree per change. These scratch worktrees accumulate after their pull requests merge, and `bu` ignores them by design. The `wtprune` helper removes worktrees and then runs `git branch -d`. That command refuses squash-merged and rebase-merged branches, because their commits are not ancestors of `main`. As a result, the branches and often the worktrees stay behind.
- **Decision:** `bu prune` considers every registered linked worktree that is not the main checkout, the configured repository path, or a configured bench. It removes one only when the folder exists, the worktree is unlocked, clean (ignored files excepted), has no merge, rebase, or cherry-pick in progress, and is attached to a branch that is neither the main branch nor a bench stand-in. GitHub must also report no open pull request and exactly one merged pull request whose head commit equals local `HEAD`. Closed, unmerged attempts beside that merge do not block. Immediately before each removal, `bu` lists the worktrees and repeats every check. It then runs `git worktree remove <path>` without `--force` and deletes the branch with `git update-ref -d refs/heads/<branch> <expected-oid>`. If the ref moved, Git refuses the delete and `bu` reports the branch as kept. Remote branches are never touched. Registered worktrees whose folders are missing are cleaned by one `git worktree prune`. `bu` skips that prune when a configured bench or the main checkout is also missing, because Git cannot limit the prune to scratch entries. `bu prune --dry-run` prints the same classification without changes.
- **Alternatives:** Reusing `wtprune` was rejected because `git branch -d` asks whether the commits are in `main`, and that question has the wrong answer for squash merges. `git branch -D` fixes the squash case but deletes unpushed commits with no proof. Deleting on pull-request state alone was rejected because commits made after the merged head would be lost. This is the same proof boundary as `docs/adr/force-recycle-merged-benches-001.md`. `git worktree remove --force` was rejected because it deletes uncommitted and untracked work and overrides locks. Without `--force`, Git remains a second guard after the recheck.
- **Consequences:** Squash-merged and rebase-merged scratch work is cleaned once GitHub holds the exact local tip. Dirty, locked, detached, unmerged, or diverged worktrees stay untouched and each gets a one-line reason. Ignored files inside a removed worktree are deleted with its folder. Removing a scratch worktree also deletes its `HEAD` reflog, so the merged pull request becomes the only record of the commits. The branch's `branch.<name>.*` configuration and remote-tracking refs remain. A failed removal or deletion is an operational error and makes the command exit nonzero. A moved ref is a safe outcome, not a failure. The worktree that contains the current directory is skipped, so the shell is not left in a deleted folder.
