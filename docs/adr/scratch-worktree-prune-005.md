# ADR-005: Prune scratch worktrees whose newest closed pull request holds HEAD [status: accepted]

- **Context:** ADR-001 skipped every scratch worktree whose pull requests were all closed without merging, with the row `pull request #N was closed without merging`. Abandoned and superseded attempts therefore stayed on disk until someone removed them by hand. The daily `bu-prune` job could not clean them. The commits of a closed pull request stay on GitHub as `refs/pull/<N>/head`, the same record that ADR-001 and ADR-004 rely on for a merged pull request.
- **Decision:** When a branch has no open pull request and no merged pull request, the newest closed pull request is the proof. Newest means the highest number, because GitHub numbers pull requests in creation order. That closed head must equal local `HEAD`, or local `HEAD` must be a strict ancestor of it, with the same ancestry check as ADR-004. Every other check from ADR-001 to ADR-004 and `prune.keep` still applies, including the recheck immediately before removal. An older closed pull request whose head matches proves nothing when a newer closed one does not match. A merged pull request still wins over any closed pull request, newer or older, so ADR-001 is unchanged for branches that merged. The rule is on by default in every configured repository, and the daily job acts on it after the next install. Rows name how the pull request ended: `closed pull request #N; would remove worktree and branch`, or `closed pull request #N has head X, not local HEAD Y` when the proof fails.
- **Alternatives:** An opt-in `[prune] closed = true` setting was rejected because closed attempts pile up in every repository, and the proof boundary is the same as for a merge. A `bu prune --closed` flag was rejected because the daily job would never use it. Accepting any closed pull request whose head matches was rejected because a later, different attempt shows that the branch moved on from that head.
- **Consequences:** A pull request that a bot closed as stale, or that Marcus closed to reopen later, loses its local worktree and branch once the head matches. The commits stay on GitHub under `refs/pull/<N>/head`, so `git fetch origin pull/<N>/head` restores them, and reopening the pull request still works. Local work after the closed head still blocks the worktree, as ADR-004 requires. `bu recycle` keeps its merged-only rule from `docs/adr/force-recycle-merged-benches-001.md`.
